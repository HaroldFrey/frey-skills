# bash-defensive-patterns 使用说明

## 这是什么

一个**知识型 skill**，将 Bash 防御性编程的最佳实践封装在内部。当你编写 Shell 脚本时，AI 会自动加载这套规范，确保生成的脚本安全、健壮、可维护。

**不是执行工具**，而是**编码规范书**——它教 AI 怎么写好 Bash，而不是替你做某件事。

---

## 适用场景

| 场景 | 说明 |
|------|------|
| 生产环境自动化脚本 | 需要稳定运行，不能遇错不管 |
| CI/CD 流水线脚本 | 构建/部署/测试自动化 |
| 系统管理工具 | 批量操作文件、进程、服务 |
| 部署脚本 | 需支持预览（dry-run）和回滚 |
| 跨平台脚本 | 需要兼容不同 Linux 发行版 |

## 核心规则速查

skill 强制执行以下 14 条规则：

| # | 规则 | 含义 | 为什么重要 |
|---|------|------|-----------|
| 1 | `set -Eeuo pipefail` | 严格模式：遇错即停 | 脚本默默出错你都不知道 |
| 2 | `"$变量"` 加引号 | 所有变量加双引号 | 防止空格导致单词分裂 |
| 3 | `[[]]` 代替 `[]` | 使用增强条件判断 | 更安全，支持正则，不会空值报错 |
| 4 | `trap ... ERR` | 捕获错误并报告 | 出错了知道在哪一行 |
| 5 | 输入校验 | 检查文件存在、权限、格式 | 不在执行中途才发现参数有问题 |
| 6 | 函数封装 | 功能模块化、命名清晰 | 逻辑清晰、可复用、可测试 |
| 7 | 结构化日志 | 带时间戳 + 级别（INFO/WARN/ERROR/DEBUG） | 出问题时能追溯 |
| 8 | dry-run 模式 | `-d` 参数，只预览不执行 | 确认安全再真正运行 |
| 9 | `mktemp` + `trap` | 临时文件自动创建和清理 | 不残留垃圾文件 |
| 10 | 幂等性 | 重复执行结果一致 | 脚本跑两次不会搞坏东西 |
| 11 | 文档要求 | 头部写清依赖和最低版本 | 别人（包括未来的你）知道怎么用 |
| 12 | 测试错误路径 | 确保异常处理真的有效 | 不仅要能正常跑，还要可控地失败 |
| 13 | `command -v` | 检查命令是否存在 | 比 `which` 更跨平台 |
| 14 | `printf` > `echo` | 使用 printf 输出 | echo 在不同系统行为不一致 |

## 效果对比

### ❌ 不遵循规范的脚本
```bash
#!/bin/bash
mkdir /tmp/mydir
cp $file /tmp/mydir          # $file 未定义 → 静默复制空内容
rm -rf /tmp/mydir/$old        # $old 为空 → 删掉整个目录！
```

### ✅ 遵循规范的脚本
```bash
#!/bin/bash
set -Eeuo pipefail
: "${file:?file 未设置}"       # 未定义直接报错退出
[[ -d "$dest" ]] || exit 1    # 目标目录必须存在
cp "$file" "$dest"             # 变量加引号，安全复制
```

## 注意事项

1. **Windows 环境**：本 skill 针对 Bash（Linux/macOS/Git Bash/WSL），不适用于 PowerShell 或 CMD
2. **GNU 工具**：部分模式依赖 GNU 版本的工具（如 `mktemp --suffix`）
3. **可修改**：你可以编辑 `SKILL.md` 或 `details.md` 来添加自己团队的编码规范
4. **与其他 skill 配合**：可以和 `/ls`、`/pwd` 等执行型 skill 同时使用，互不影响
