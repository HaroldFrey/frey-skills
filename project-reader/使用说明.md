# project-reader — 项目深度阅读与分析

对新克隆或已有的项目进行全量分析，生成结构化报告，帮助快速理解项目架构和核心逻辑。

## 触发方式

- **手动**：`/project-reader` 或 `/project-reader <项目路径>`
- **自动**：消息包含"阅读项目""理解项目""分析项目""了解这个项目"

## 功能说明

| 分析维度 | 内容 |
|---------|------|
| 项目概述 | 用途、技术栈、入口点 |
| 目录结构 | 完整文件树 + 分类统计 |
| 架构设计 | 分层架构 + 调用关系图 + 数据流 |
| 关键文件 | 核心逻辑、配置项、接口约定 |
| 依赖环境 | 外部工具、版本要求、平台要求 |
| 使用指南 | 构建、运行、测试、常见修改 |

## 输出

在项目根目录 `doc_reader/` 下生成 6 份 Markdown 文档：

```
doc_reader/
├── 00_项目概述.md
├── 01_目录结构与文件清单.md
├── 02_架构设计.md
├── 03_关键文件详解.md
├── 04_依赖与运行环境.md
└── 05_使用指南.md
```

## 使用示例

### 分析当前项目

```
/project-reader
```

### 分析指定项目

```
/project-reader ~/clone/新项目
```

### 自然语言触发

```
帮我分析一下这个项目
这是一个什么项目，帮我理解一下
阅读并解析当前目录的项目
```

### 分析后追问

报告生成后可以继续深入：

```
深入分析 control.sh
帮我画一下完整的调用关系图
汇总所有脚本的配置项
```

## 质量保证

报告生成后，自动调用 `/full-review` 对 `doc_reader/` 下的产物进行交叉检查：
- 配置值、行号引用、流程描述是否与实际代码一致
- 发现问题 → 用户确认 → 修改 → 重新检查 → 循环直到 0 问题
- 不限制迭代次数

## 与其他 skill 联动

| 项目类型 | 自动调用 |
|---------|---------|
| Bash 脚本项目 | `/bash-defensive-patterns` |
| FPGA/Verilog 项目 | `/verilog-sv-language` + `/vivado-synth` |
| 通用/其他 | 自主分析 |

## 经验积累

分析完成后，如发现值得沉淀的经验（新项目模式、分析维度、用户偏好），会向用户提议追加到 `learnings.md`。

> ⚠️ 所有经验写入必经用户确认。
