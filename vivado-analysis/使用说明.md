# vivado-analysis 使用说明

## 这是什么

一个**分析型 skill**，专门帮助你解读 Vivado 的设计分析报告和做时序收敛决策。覆盖 `report_timing`、`report_timing_summary`、`report_qor_assessment`（QoR 评分）、`report_design_analysis`（路径特性/复杂度/拥塞分析）、`report_methodology`（设计规则合规）、`report_cdc`（跨时钟域检查）等。

**注意**：此 skill 提供**分析和解读知识**——帮你理解报告、找到根因、制定收敛策略。实际执行 TCL 命令请用 `vivado-tcl`，修改约束请用 `vivado-constraints`。

---

## 适用场景

| 场景 | 说明 |
|------|------|
| 看不懂时序报告 | 帮你解读 `report_timing` 的每个字段 |
| 时序不收敛 | 提供 Setup/Hold 违例的系统化解决方案 |
| QoR 评分 | 理解 1-5 分评分含义和每个类别的 REVIEW 原因 |
| 拥塞分析 | 判断拥塞等级，给出缓解策略 |
| 跨时钟域检查 | 解读 `report_cdc`，处理 CDC 违例 |
| 资源利用率 | 解读 `report_utilization`，分析 BRAM/DSP 超用问题 |
| 设计规则检查 | 方法论合规检查，处理 DRC 违例 |

## 核心知识速查

### Slack 公式

| 分析类型 | 公式 | 含义 |
|---------|------|------|
| Setup/Recovery | `slack = data_required_time - data_arrival_time` | 正 = 达标，负 = 违例 |
| Hold/Removal | `slack = data_arrival_time - data_required_time` | 正 = 达标，负 = 违例 |

### QoR 评分解读

| 分数 | 含义 | 你应该做什么 |
|------|------|-------------|
| 1 | 设计很可能跑不完实现流程 | 大幅重新设计 |
| 2 | 能跑完但一定不满足时序 | 重大优化 |
| 3 | 很可能不满足时序 | 针对性优化 |
| 4 | 很可能会满足时序 | 微调即可 |
| 5 | 满足时序 | 直接生成比特流 |

### 五个评估维度

| 维度 | 检查什么 |
|------|---------|
| Utilization | 整体/SLR/Pblock 资源使用 |
| Netlist | 逻辑结构、DONT_TOUCH、高扇出 |
| Clocking | Setup/Hold 路径上的时钟偏移 |
| Congestion | 引起布线拥塞的网表结构 |
| Timing | 每时钟组的 WNS/TNS/WHS/THS |

## 时序收敛决策树

### Setup 违例 → 按顺序排查

```
1. 检查逻辑级数 (report_design_analysis)
   → 太多级 → 插入流水线寄存器 / 用 -global_retiming
2. 检查扇出 (report_design_analysis)
   → 过高 → 加 MAX_FANOUT 属性 / phys_opt 复制
3. 检查物理扩散 (report_design_analysis -congestion)
   → 过大 → Pblock 布图规划
4. 检查时钟偏移
   → 负偏移 → 审查时钟树、BUFG 位置
5. 检查时序例外约束
   → 缺失/错误 → 修正 XDC 约束
```

### Hold 违例 → 按顺序排查

```
1. 检查 fast-corner 延迟
   → 数据路径太短 → phys_opt_design hold fix
2. 检查时钟偏移
   → 正偏移过大 → 审查时钟树平衡
3. 检查跨 SLR 路径（SSI 器件）
   → SLR 穿越 → SLR 感知布局
```

### 拥塞 ≥ Level 5 → 缓解策略

```
1. 检查利用率 → > 80% LUT → 减小设计规模或用面积优化综合
2. 检查高扇出 → 复制驱动 (phys_opt_design fanout opt)
3. 尝试拥塞策略 → vivado-impl: Congestion_* 策略
4. 布图规划 → 用 Pblocks 分散逻辑
```

## 报告选择指南

| 你的需求 | 用什么命令 | 时机 |
|---------|-----------|------|
| 快速时序签核 | `report_timing_summary` | 实现后，比特流前必须执行 |
| 分析特定失败路径 | `report_timing -from/-to/-through` | 调试具体违例 |
| 整体 QoR 评分 | `report_qor_assessment` | 布线后，评估收敛可能性 |
| 自动优化建议 | `report_qor_suggestions` | 时序卡住时 |
| 深度路径分析 | `report_design_analysis` | 分析逻辑级数/扇出/物理扩散 |
| 方法论合规 | `report_methodology` | 流程早期 |
| 资源使用 | `report_utilization` | 综合或实现后 |
| CDC 检查 | `report_cdc` | 综合后 |
| 拥塞分析 | `report_design_analysis -congestion` | 布局后 |

## 注意事项

1. **综合后时序不准**：综合后的时序用估算布线延迟，只有 `post-route` 的时序才准确
2. **QoR 自动终止**：可设置 `MIN_RQA_SCORE` 属性，评分低于阈值自动停止
3. **消息降级/升级**：可用 `set_msg_config` 把 Critical Warning 降级或把 Warning 升级
4. **Waiver 不可删除 AMD IP 的**：只能 waiver 自己设计的部分
