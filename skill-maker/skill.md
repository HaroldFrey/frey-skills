# Skill Maker — Skill 制作工作流

帮助用户从描述到交付完成一个自定义 skill。全程引导用户试用、反馈、迭代。

---

## 第零步：阅读经验文档（强制执行）

> ⚠️ 在开始任何 skill 制作之前，**必须先阅读**本文档所在目录下的 `skill-making-experience.md`。

该文档包含了基于 17+ 个 skill 的制作和迭代经验，涵盖：

- 目录结构与命名规范（最易踩坑）
- Frontmatter 设计技巧
- 四种 Skill 类型的设计模式
- Workflow 检查点设计
- 手动/自动模式设计原则
- Skill 间调用关系
- 文档规范
- 权限与配置
- 常见踩坑与解法

阅读完经验文档后，对照其中的"快速自检清单"检查用户需求，确保不犯基础错误。

---

## 流程概览

```
理解需求 → 🛑 确认清单 → 生成 skill → 🛑 确认内容 → 🛑 试用
    ↑                                                       │
    └────────── 用户反馈 + AI 建议 → 迭代修改 ←───────────────┘
                                               ↓
                                          🛑 用户满意 → 完成
```

---

## 阶段 1：理解需求

> 与 `/req-analysis` 逻辑一致，但更聚焦 skill 场景。

用户描述想要的 skill 后，追问以下几点直到清晰：

1. **skill 叫什么名字**？（英文名，如 `check-timing`）
2. **什么时候触发**？手动 `/命令`？还是自动匹配关键词？
3. **具体做什么**？一步一步描述 skill 的行为
4. **放在哪**？全局（`C:\Users\...\.claude\skills\`）还是项目级？
5. **需要调用其他 skill 吗**？（如 `bash-defensive-patterns`）

不限轮次追问。全部理清后，生成一份**确认清单**：

```markdown
## Skill 需求确认
- 名称：xxx
- 触发：/xxx 手动 / 关键词自动匹配
- 行为：1.xxx 2.xxx 3.xxx
- 位置：全局 / 项目级
- 联动：需要调用 xxx skill / 无

请确认以上内容，回复"通过"开始生成。
```

> ⚠️ **必须用户确认后才进入生成阶段。** 不受任何模式影响。

---

## 阶段 2：生成 Skill

确认通过后，创建 skill 文件：

1. 创建目录 `skills/<skill名>/`
2. 写入 `skill.md`，包含：
   - 正确的 frontmatter（`name` + `description`）
   - 清晰的行为指令
   - 如果涉及编码规范，注明内部调用哪些 skill
3. **同步生成 `使用说明.md`**，包含：
   - skill 名称和一句话简介
   - 触发方式（手动 `/命令` / 自动匹配）
   - 功能说明（这个 skill 做什么）
   - 使用示例
   - 与其他 skill 的联动关系（如有）
4. 🛑 **展示 skill 内容给用户，确认无误后再进入试用**

```
📄 Skill 内容如下：

<展示 skill.md 全文>

请确认内容无误后回复"通过"，然后进入试用阶段。
```

---

## 阶段 3：提示用户试用 🛑

```
✅ Skill 已创建：/<skill名>

请现在试用一下：输入 /<skill名> 或描述相关需求，看看效果是否符合预期。

试用完成后回复我：
  - "效果不错，但是..." → 我会根据你的反馈修改
  - "满意" → 完成
```

**必须等待用户试用并回复后才进入下一阶段。** 不等用户试用就继续是不允许的。

---

## 阶段 4：收集反馈 + 给出建议

用户试用后，主动从以下角度给出改进建议：

| 建议方向 | 说明 |
|---------|------|
| **完善使用说明** | `使用说明.md` 是否需要补充更多示例或细节？ |
| **添加代码示例** | skill 中是否需要内嵌代码模板？ |
| **添加参考资料** | 是否需要 `references/` 子目录存放详细文档？ |
| **添加示例项目** | 是否需要 `examples/` 子目录，放入完整演示？ |
| **与其他 skill 联动** | 是否需要调用现有 skill？如 `bash-defensive-patterns` |
| **完善触发条件** | `description` 字段是否足够准确，让 AI 自动匹配？ |
| **添加参数支持** | skill 是否需要支持参数（如 `--auto`）？ |
| **参考已有 skill 结构** | 是否有类似的已有 skill 可以参考其目录结构？ |

向用户展示建议列表，用户可选择采纳或忽略。

---

## 阶段 5：迭代改进

用户提出修改意见 → 修改 skill.md → 让用户再次试用 → 循环直到用户说"满意"。

每次修改后，清晰列出本次改了什么。

---

## 阶段 6：完成

用户满意后，提醒：

```
🎉 Skill 已就绪：/<skill名>

你现在可以在任何项目中使用它。如需再次修改，随时对我说 "修改 /<skill名>，增加 XXX 功能"。
```

---

## 行为准则

1. **需求确认不可跳过**——阶段 1 末尾必须生成确认清单，用户确认后才进入生成
2. **内容确认不可跳过**——阶段 2 展示 skill.md 内容，用户确认后才进入试用
3. **不等用户试用就不能继续**——阶段 3 是强制等待点
4. **主动给建议**——用户可能不知道 skill 还能加什么，AI 应该主动列举
5. **每次修改后让用户再试**——不假设用户已经满意
6. **支持全局和项目级两种位置**——默认全局，用户说"这个项目"则放项目级
7. **文件结构提醒**：每个 skill 目录下至少包含 `skill.md` + `使用说明.md`
