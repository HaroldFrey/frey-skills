# Git Pull — 检查远程更新并同步本地

自动检查远程仓库是否有新提交，有则拉取同步，无则告知已是最新。

---

## 参数

| 参数 | 说明 |
|------|------|
| 无参数 | 检查当前工作目录 |
| `/git-pull <目录1> [<目录2> ...]` | 依次检查并同步多个指定目录 |

---

## 执行流程

### 步骤 1：确定要检查的目录列表

- **无参数** → 检查当前工作目录
- **有参数** → 依次处理用户指定的每个目录

### 步骤 2：逐个目录执行检查与同步

对每个目录执行以下操作：

**1. 确认是 git 仓库**

执行 `git status` 检查：

- 是 git 仓库 → 继续
- 不是 git 仓库 → 提示"`<目录>` 不是 git 仓库，跳过"并继续下一个目录

**2. 获取远程最新状态**

执行 `git fetch`（只拉取远程状态，**不修改本地文件**）：

- 成功 → 继续
- 网络失败 → 按步骤 3 的重试机制处理

**3. 对比本地与远程**

执行 `git status`，根据输出判断：

| 状态 | 判断 | 处理 |
|------|------|------|
| `Your branch is behind 'origin/main'` | 远程有新提交 | 检查本地是否有未提交修改（见下） |
| `Your branch is ahead of 'origin/main'` | 本地领先远程 | 提示"本地有未推送的提交，远程无新内容" |
| `up to date` | 完全同步 | 提示"已是最新" |
| 其他分支状态 | 按实际输出解读并告知用户 | — |

**4. 同步（远程有更新时）**

- **本地工作区干净** → 执行 `git pull`，报告同步结果：更新了哪些文件、新提交号
- **本地有未提交修改** → 提示用户：
  ```
  ⚠️ 远程有新提交，但本地有未提交的修改（可能造成冲突）。
  为避免覆盖你的工作，请先选择处理方式：
  - "提交" → 我先帮你 git add + commit 再 pull
  - "暂存(stash)" → 我先 git stash 再 pull（之后可 git stash pop 恢复）
  - "跳过" → 本次不拉取该目录
  ```
  等待用户决定，**不擅自 stash 或覆盖**

**5. pull 遇冲突**

- 停止，展示冲突文件列表
- 给出解决建议（手动解决冲突后 `git add` + `git commit`，或告知用户需要放弃时用 `git merge --abort`）
- **不盲目 merge/reset**

### 步骤 3：网络重试机制

`git fetch` / `git pull` 因网络原因失败（connection reset、timeout 等）时：

1. 等待 **10 秒** → 重试第 1 次
2. 仍失败 → 等待 **10 秒** → 重试第 2 次
3. 仍失败 → 等待 **10 秒** → 重试第 3 次
4. **3 次均失败** → 告知用户："网络不稳定，3 次均失败。本地仓库未受影响，请稍后手动执行 `git pull`"

### 步骤 4：汇总结果

多目录检查完成后，输出汇总表：

```
📋 同步结果汇总：
| 目录 | 状态 |
|------|------|
| D:\Stduy\WSL_Use | ✅ 已同步（新增 2 个提交） |
| D:\Stduy\AI-Agent | ✅ 已是最新 |
| D:\Stduy\xxx | ⚠️ 非 git 仓库，跳过 |
```

---

## 行为准则

1. **每一步执行前简要说明正在做什么**
2. **本地有未提交修改时不擅自 stash/覆盖**——先提示用户，等用户决定
3. **pull 有冲突时停止并展示**——不盲目 merge/reset
4. **多目录时逐个处理**——一个目录失败不影响其他目录继续检查
5. **`git fetch` 只拉取状态不修改本地文件**，确认远程有更新后才 `git pull`
6. **git 操作失败时打印错误信息并停止**，不盲目重试
