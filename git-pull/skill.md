# Git Pull — 递归检查远程更新并同步本地

自动递归扫描指定根目录，发现其中所有 git 仓库，检查每个仓库的远程是否有新提交，有则拉取同步，无则告知状态。

---

## 参数

| 参数 | 说明 |
|------|------|
| 无参数 | 检查当前工作目录（按模式判断，见步骤 2） |
| `/git-pull <目录1> [<目录2> ...]` | 依次处理每个目录（单仓库或递归扫描，自动判断） |

> 💡 **两种模式自动判断**：
> - 传入目录**本身是 git 仓库** → 单仓库模式：直接检查该仓库（如 `/git-pull D:\Stduy\WSL_Use`）
> - 传入目录**不是 git 仓库** → 递归扫描模式：扫描其所有子目录中的 git 仓库（如 `/git-pull D:\Stduy`）

---

## 执行流程

### 步骤 1：确定目录列表

- **无参数** → 目录 = 当前工作目录
- **有参数** → 依次处理用户指定的每个目录

### 步骤 2：判断模式，生成仓库列表

对每个目录：

1. **检查目录本身是否为 git 仓库**（存在 `.git` 子目录）
   - **是** → 单仓库模式：仓库列表 = 该目录本身
   - **否** → 递归扫描模式：递归查找该目录下所有含 `.git` 的目录，生成仓库列表
2. 汇总生成仓库列表

### 步骤 3：逐个仓库检查与同步

对每个仓库执行：

**1. 获取远程最新状态**

执行 `git fetch`（只拉取远程状态，**不修改本地文件**）：

- 成功 → 继续
- 网络失败 → 按步骤 4 的重试机制处理；重试仍失败 → 该仓库标记"网络失败"，继续下一个仓库

**2. 判断仓库状态**

执行以下命令计算状态：

```bash
git branch --show-current          # 当前分支
git rev-list --count HEAD..origin/<分支>    # behind：落后远程的提交数
git rev-list --count origin/<分支>..HEAD    # ahead：本地领先的提交数
git status --porcelain | wc -l     # 未提交修改的文件数
```

> 没有配置 `origin` 远程 → 标记"无远程"，跳过

**3. 按状态处理**

| 状态 | 判断条件 | 处理 |
|------|---------|------|
| **落后远程** | behind > 0 且 ahead = 0 | 检查本地工作区：干净 → 执行 `git pull`；有未提交修改 → 标记"落后且有修改，跳过" |
| **已是最新** | behind = 0 且 ahead = 0 | 标记"已是最新" |
| **本地超前** | ahead > 0 且 behind = 0 | 标记"本地超前 N 个提交（未推送）" |
| **分叉** | behind > 0 且 ahead > 0 | 标记"分叉：落后 N / 超前 M，需手动处理" |
| **有未提交修改** | 工作区非干净（与以上叠加时） | 在状态描述中追加"本地有 X 个未提交修改" |

**4. pull 遇冲突**

- 停止该仓库的 pull，标记"冲突"，展示冲突文件列表
- 给出解决建议（手动解决冲突后 `git add` + `git commit`，或 `git merge --abort` 放弃）
- **不盲目 merge/reset**

### 步骤 4：网络重试机制

`git fetch` / `git pull` 因网络原因失败（connection reset、timeout 等）时：

1. 等待 **10 秒** → 重试第 1 次
2. 仍失败 → 等待 **10 秒** → 重试第 2 次
3. 仍失败 → 等待 **10 秒** → 重试第 3 次
4. **3 次均失败** → 该仓库标记"网络失败"，继续下一个仓库

### 步骤 5：汇总结果

全部仓库处理完后，输出汇总表：

```
📋 同步结果汇总（扫描根目录：D:\Stduy，发现 X 个 git 仓库）

| 仓库 | 状态 |
|------|------|
| D:\Stduy\WSL_Use | ✅ 已同步（新增 2 个提交） |
| D:\Stduy\AI-Agent | ✅ 已是最新 |
| D:\Stduy\peakrdl_stduy | ⚠️ 本地超前 2 个提交（未推送） |
| D:\Stduy\xxx | ⚠️ 落后 3 且本地有 2 个未提交修改，跳过 |
| D:\Stduy\yyy | ⚠️ 分叉：落后 1 / 超前 2，需手动处理 |
| D:\Stduy\zzz | ❌ 网络失败（3 次重试均失败） |

需要推送本地超前提交？用 /git-push
```

## 行为准则

1. **每一步执行前简要说明正在做什么**
2. **递归扫描**：只扫描给定根目录内的仓库，不越界扫描其他盘
3. **本地有未提交修改时不擅自 stash/覆盖**——该仓库跳过，汇总中说明
4. **pull 有冲突时停止该仓库并展示**——不盲目 merge/reset
5. **`git fetch` 只拉取状态不修改本地文件**，确认远程有更新且工作区干净后才 `git pull`
6. **一个仓库失败不影响其他仓库**——逐个处理，最后汇总
7. **git 操作失败时打印错误信息并停止该仓库**，不盲目重试
