# /git-pull — 检查远程更新并同步本地

## 功能
检查 git 仓库的远程是否有新提交，有则自动 `git pull` 同步。**两种模式自动判断**：
- **单仓库模式**：传入目录本身是 git 仓库 → 直接检查该仓库
- **递归扫描模式**：传入目录不是 git 仓库 → 自动扫描其所有子目录，发现其中的 git 仓库并逐个检查

## 触发方式
- 手动：`/git-pull`
- 自动匹配：说"检查更新"、"同步仓库"、"拉取最新"、"git pull"

## 使用示例

### 检查当前目录
```
/git-pull
```
当前目录是仓库 → 单仓库模式；不是仓库 → 递归扫描其子目录。

### 单仓库模式：指定一个仓库目录
```
/git-pull D:\Stduy\WSL_Use
```
D:\Stduy\WSL_Use 本身是 git 仓库 → 只检查它。

### 递归扫描模式：指定一个根目录
```
/git-pull D:\Stduy
```
D:\Stduy 不是 git 仓库 → 扫描其下所有子目录，自动发现全部 git 仓库（AI-Agent、WSL_Use、Makefile 等）逐个检查同步。

### 多个目录
```
/git-pull D:\Stduy C:\Users\28968\.claude\skills
```
依次处理每个目录（各自按模式判断）。

## 工作流程
```
确定目录列表 → 逐个目录判断模式（自身是仓库？单仓库 : 递归扫描）
  → 对每个仓库：git fetch → 计算 behind/ahead/未提交修改
  → 落后且工作区干净 → git pull
  → 其他状态（超前/分叉/有修改/无远程）→ 记录并在汇总中告知
  → 输出汇总表
```

## 状态处理规则
| 仓库状态 | 处理 |
|---------|------|
| 落后远程且工作区干净 | ✅ 自动 git pull |
| 落后远程但有未提交修改 | ⚠️ 跳过，汇总告知（不擅自覆盖） |
| 已是最新 | ✅ 汇总告知 |
| 本地超前（未推送） | ⚠️ 汇总告知（可用 /git-push 推送） |
| 分叉（既超前又落后） | ⚠️ 汇总告知，需手动处理 |
| 网络失败 | ❌ 重试 3 次（10 秒间隔）后标记，继续其他仓库 |
