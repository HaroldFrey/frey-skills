# /git-push — 智能推送到 GitHub

## 功能
自动完成 `git add → commit → push` 流程。**两种模式自动判断**：
- **直接推送模式**：传入目录本身是 git 仓库（或无参数=当前目录）→ 直接 add/commit/push
- **扫描模式**：传入目录不是 git 仓库 → 递归扫描其所有子目录，找出需要推送的仓库，**报告给用户，由用户决定**推哪些

## 触发方式
- 手动：`/git-push`
- 自动匹配：说"推送代码"、"推送到GitHub"、"git push"

## 使用示例

### 直接推送当前目录
```
/git-push
```
自动暂存 → 生成 commit message → 推送 main 分支。

### 直接推送指定仓库
```
/git-push D:\Stduy\WSL_Use
```
D:\Stduy\WSL_Use 本身是 git 仓库 → 直接推送。

### 扫描模式：检查根目录下所有仓库
```
/git-push D:\Stduy
```
D:\Stduy 不是 git 仓库 → 扫描其所有子目录，列出需要推送的仓库（🔄 有未推送提交 / 📝 有未提交修改），**等你决定**：
- 回复"全部推送" → 逐个处理
- 回复"推 <仓库名>" → 只推送指定仓库
- 回复"跳过" → 不推送

## 工作流程
```
判断模式（目录是 git 仓库？直接推送 : 扫描模式）
  ├─ 直接推送：检查仓库 → add → commit（自动生成 message）→ push（重试 3 次）
  └─ 扫描模式：递归发现仓库 → 判断每个是否需要推送 → 报告 → 🛑 等用户决定 → 按选择推送
```

## 参数
| 参数 | 说明 |
|------|------|
| 无参数 | 直接推送当前工作目录 |
| `<目录>`（是 git 仓库） | 直接推送该仓库 |
| `<目录>`（不是 git 仓库） | 扫描模式，报告后由用户决定 |

## 网络重试
推送因网络失败自动重试：等 10 秒 → 重试，最多 3 次；仍失败告知用户手动推送。
