# /sv-dev-workflow — Verilog/SystemVerilog 模块开发全流程

## 功能
编排型 skill，管理 RTL 模块 + 测试平台 + 仿真验证三阶段开发。支持多模块项目。内部自动调用 `/verilog-sv-language`（编码规范）、`/full-review`（补充审查）和 `/vivado-synth`（综合策略）；仿真验证使用开源工具链 iverilog / gtkwave + Python 标准库。

## 触发方式
- 手动：`/sv-dev-workflow`
- 自动匹配：说"写模块"、"RTL设计"、"Verilog开发"、"FPGA模块开发"

## 流程概览

**Phase A — RTL 模块：**
| 阶段 | 说明 |
|------|------|
| A0. 需求分析 | 不限轮次追问，生成需求文档 🛑 |
| A1. 微架构设计 | 含设计思路 6 子节、FSM 详表、逐周期波形 |
| A2. RTL 编码 | 加载 verilog-sv-language + 语法解析 |
| A3. 综合审查 | **循环直到通过**：verilog-sv-language 代码级 + full-review 补充（文档一致/资源预估/覆盖缺口）→ 发现问题即修复回归重审 |
| A4-A7 | 追踪 → 迭代 → 最终 → 全面检查 |

**Phase B — 测试平台：** 镜像 Phase A 流程。

**Phase C — 仿真验证循环（大阶段）：**
| 阶段 | 说明 |
|------|------|
| C0. 环境与脚本准备 | 工具检查（iverilog/vvp/gtkwave/python）+ 编写 VCD 分析脚本（Python 标准库）🛑 |
| C1. 编译 + 仿真 | iverilog -g2012 → vvp → 生成 VCD |
| C2. 波形分析 | 运行 check_vcd.py + gtkwave 人工定位，脚本随问题增量补充断言 |
| C3. 问题定位与修复 | **先查 TB/脚本再查 RTL**；四分类回退：方案设计 A1 / 编码 A2 / TB与脚本 B2 / 工具兼容就地绕过 |
| C4. 回归 | 重跑 C1→C2，直到终止条件：ALL PASS + 脚本全过 + 连续一轮无新问题 |
| C5. 全面检查 | C 阶段内部一致性 + 全项目复查，通过后 C 阶段结束 🛑 → README |

## 模式
- 🔧 手动（默认）：每个检查点等待确认
- 🤖 自动：`/sv-dev-workflow --auto`

> ⚠️ A0/B0 需求确认不受模式影响，必须人工确认。

## 内部 Skill 调用
