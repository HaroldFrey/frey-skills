# RTL 开发通用经验（抽象原则）

> 本文件从具体项目**抽象**出可复用的开发原则：架构模式、编程风格红线、状态机要点、生成器模式、验证方法论、资源评估方法、协作流程。原则即本体，可直接套用；实例仅作溯源参考。
>
> **来源项目**（完整上下文见仓库）：Register-Config-Module——CSV → Python 生成器 → 可综合 SystemVerilog RTL 的寄存器配置模块（APB 3.0 / AXI4-FULL 双版本，v4.1 分层架构）。
> 仓库：<https://github.com/HaroldFrey/Register-Config-Module>（分支 `reg_cfg_plus`）
>
> **适用 skill**：sv-dev-workflow（iverilog 开源链）与 sv-dev-workflow-vivado（Vivado 链）共用——两 skill 的 Phase A/B 完全相同，仅 Phase C 验证工具链不同。

## 1. 架构抽象：四层职责分离模式

```text
调度层（哑序列器：只发命令、不认知语义，持配置存储）
  → 分派层（纯组合：分派/汇聚/路由/广播，无 FSM、无寄存器）
    → 语义层（每种行为一个模块，统一接口）
      → 协议层（总线相位时序原语，顶层例化）
```

1. **各层只做一件事**，层间接口最小化——调度层不认知语义、语义层不接触总线。
2. **路由汇聚层做纯组合**（无状态）：复杂互联收敛到一个无 FSM 模块，其余层保持简单。
3. **共用与专属分离**：可复用代码（与协议无关）独立成文件、多协议零改动复用；协议专属代码收敛到最少文件（原语 + 顶层模板）。
4. **顶层仅例化**：观测信号纯组合直通（不锁存、不加工）——可观测性与结构简单兼得。
5. **扩展点显式化**：加"行为" = 加 1 个语义模块 + 1 条脚本映射；加"协议" = 加原语 + 顶层模板，其余零改动。

**可读性教训**：互联信号多的纯组合模块，用"形态分组"（选通 / 汇聚 / 路由 / 广播）组织声明区 + 注释排版解决，不要因此改架构。

## 2. 接口契约抽象：最小完备 + 电平保持

1. **电平保持握手**：`请求 && 空闲` = 接受沿（请求保持至被接受）——比脉冲握手鲁棒（脉冲易丢、需 FIFO 缓冲）。
2. **无操作命令化**：wait/空转也是原语的一个命令位（`xfer_wait=1`），不做独立模块、不走旁路逻辑。
3. **信号集最小完备**：多一个冗余、少一个不完备；**数据/方向必须显式选择**，禁止用 OR 合并复用（残留值污染）。
4. **完成沿组合输出**：`done = 状态条件 && 握手条件`，done 拍数据有效——子模块只在 done 拍采样，省 1 拍锁存。

## 3. 编程风格红线（违反即返工）

| 原则 | 具体做法 | 动机 |
| --- | --- | --- |
| 握手条件显式写全 | 恒 1 侧也写出（`arvalid && arready` 而非只写 `arready`） | 可读性、防误读（"即便是恒为 1，也要写上"） |
| 例化显式列全端口 | 未用信号 `.port()` 显式悬空 | 防漏连、防工具报错（"有些工具可能会报错"） |
| 状态命名语义化 | `IDLE` / `<事务>_PEND`（请求待接受）/ `WAIT_<事务>_DONE`（等完成） | 名字即语义；避免"挂起""等待中"等模糊词 |
| 状态图注释同源 | ASCII 方框 + 箭头 + 转移条件，框宽 = 名长 + 6、上下边框严格等宽（配校验脚本） | 图与代码同步演进，防漂移 |
| 顶层零逻辑 | 观测信号纯组合直通 | "一层层传递就可以" |

## 4. 状态机抽象

1. **状态按协议阶段划分**，不按直觉/通道数拆（AXI 6 态 = IDLE/WAIT/RD_AR/RD_R/WR_AW_W/WR_B；APB 状态即相位）。
2. **AXI 写通道 AW/W 分拍独立握手**（各自完成标志）：**不能等同拍 `awready && wready`**——从设备握手后不再拉高，等同拍等待必死锁。经典坑，写 AXI 必防。
3. 完成沿组合输出（§2.4），接受沿 = `请求 && 空闲`（空闲在 IDLE 恒 1，仍显式写出）。

## 5. 生成器抽象：模板纯 RTL、脚本只组装

1. **模板与逻辑分离**：模板是纯 RTL + 占位符（`__ADDR_WIDTH__` 等），脚本只做占位符替换与数据注入（RAM_INIT）——**脚本不做逻辑生成**，产物可读、可审查、可独立综合。
2. **表驱动映射**：模板相对路径 → 输出文件名的映射表；注入类型区分（数据初始化 / 仅公共占位符）；模块名写死在模板内。
3. **无效配置由脚本剔除**（如全零掩码行），RTL 不感知——减状态分支、RTL 更简单。
4. **工具脚本参数化**：类别选择（--csv 场景 / --all / --list）；输出位置**相对脚本位置解析**（SCRIPT_DIR）而非 CWD；多总线共用同一份数据源。

## 6. 验证方法论抽象

1. **分层验证**：主 tb（几十个检查点，含观测信号脉冲采样）+ 边界场景矩阵 × 总线数 + 压力规模（千行级）。
2. tb 自带自检（ALL PASS / FAIL）；VCD 分析脚本仅标准库；数据比对用 expected 数组。
3. **陷阱（错误模式 → 预防）**：

| 错误模式 | 预防 |
| --- | --- |
| 数据文件格式隐性契约（大小写/进制不一致） | 生成端统一格式化（`0x%08X` 全大写） |
| 跨进程参数丢失（`-P DEPTH=` 空值 → 编译失败后跑旧二进制） | 重跑必须先验编译错误，不盲跑 vvp |
| 控制台编码乱码（Windows GBK） | 显式 `stdout.reconfigure(encoding='utf-8')` |
| 验证数据文件堆积 | 用完即删，只留样本 + README 记录数据↔tb 对应关系 |
| 仿真通过 ≠ 完成 | vivado 链必须加综合验证（发现仿真盲区，如 multi-driven） |

## 7. 决策抽象：否决记录制度

1. **被否决的方案必须记录"方案 + 否决原因"**，否则未来重复讨论同一问题。
2. 否决记录重点：替代方案的技术硬伤（兼容性、风格冲突、收益不成立），而非"当时没选它"。
3. 实例（典型否决类别，供参考）：interface 封装互联（仿真器兼容 + 显式原则）、宏/预处理选型（下游条件化代价 > 省 1 个文件的收益）、顶层加状态（违反零逻辑原则）。

## 8. 资源/时序评估抽象（综合前快速估算）

1. **FF**：逐模块数寄存器构成（FSM 状态位 + 命令锁存位宽 + 计数器 + 握手标志）——与配置数据行数无关，只与位宽线性。
2. **LUT**：FSM 组合 + MUX/OR/译码（位宽 × 选通级）+ 握手/比较/合并。
3. **RAM 深度敏感性**：LUT6 作 dist-RAM 上限 64 深，超深级联（×16/bit @1024 深）资源延迟失控——**深度是 dist-RAM 的唯一伸缩变量**；超深换 BRAM（同步读 +1 拍，需流水/行锁存）。
4. **关键路径链枚举**：从最深链开始（RAM 读链 / 比对链 / 完成广播链 / 接受链），估逻辑级数。
5. 估算系数：7 系列 ~0.3ns/级 LUT，UltraScale+ 提升 30~40%，布线余量 30~40%。

**实例基线**（ADDR=32 / DATA=32，估算值，综合后回填）：FF ≈ 310~330；LUT ≈ 350~500（不含 RAM）；小场景 Fmax ~220-250 MHz；1000 行 dist-RAM 场景 ~110-130 MHz（读深度是唯一瓶颈）。

## 9. 交付循环抽象（不可省步骤）

```text
改代码 → 同步注释/文档（含状态图）→ 全量验证（所有总线：主/边界/压力全跑）
  → 清理产物（生成物 + 验证数据）→ push（先 git status 确认干净）
```

**协作偏好**：
- "请分析" = 只分析等批准，讨论中不动代码——不主动越界修改。
- 命名类决定让用户拍板。
- 全量验证时所有总线都要跑；用户明确说"不验证"才跳过。
