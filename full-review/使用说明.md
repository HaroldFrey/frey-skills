# full-review — 项目全面审查

对项目目录下的代码和文档进行系统化审查，按 🔴严重 / 🟡中等 / 🟢低 三级输出问题报告，每个问题附带具体修复代码。

## 触发方式

- **手动**：`/full-review` 或 `/full-review --focus <文件名>`
- **自动**：消息包含"检查""详细检查""review""全面检查""代码审查"

## 功能说明

| 检查维度 | 内容 |
|---------|------|
| 代码逻辑 | 死循环、分支遗漏、变量未初始化 |
| 边界问题 | 空输入、glob 无匹配、退出码丢失 |
| set -e 陷阱 | `$?` 捕获中断、pipefail 隐式退出 |
| 脚本间契约 | 配置值一致性、退出码约定对齐、路径约定一致 |
| 文档一致性 | 配置值、行号引用、流程描述是否匹配实际代码 |
| 历史跟踪 | 读取 REVIEW.md 避免重复报告已知问题 |
| 变更聚焦 | 读取 CHANGELOG 重点审查变更连带影响 |
| 经验积累 | 读取 learnings.md 历史经验，审查后经用户确认追加新经验 |

## 使用示例

### 全面审查

```
/full-review
```

默认扫描当前项目目录下所有 `.sh`、`.md`、`.txt` 等文件。

### 聚焦审查

```
/full-review --focus control.sh --focus run_all.sh
```

只审查指定的两个文件，但跨文件一致性检查不受限制。

### 自然语言触发

```
帮我详细检查一下 06_code 的所有脚本
检查 run_all.sh 有没有问题
review 当前项目的文档
```

## 与其他 skill 联动

| 项目类型 | 自动调用 |
|---------|---------|
| Bash 脚本 | `/bash-defensive-patterns` |
| Verilog/SystemVerilog | `/verilog-sv-language` + `/vivado-synth` |
| Makefile | `/makefile-patterns` |

## 输出

- **终端**：分组展示所有发现，含文件:行号、问题分析、修复代码
- **文件**：同步写入 `REVIEW_report_YYYYmmdd_HHMMSS.md`，方便归档

## 经验积累

每次审查完成后，如发现值得沉淀的经验，会向用户提议追加到 `learnings.md`：

| 经验类型 | 说明 |
|---------|------|
| 审查清单补充 | 新发现的常见问题模式，后续自动加入检查 |
| 误报/免检 | 曾误报但实际无问题的情况，后续跳过 |
| 用户偏好 | 审查风格偏好（如"太啰嗦"等） |

> ⚠️ 所有经验写入必经用户确认，不会自动执行。
